# Security policy

## Supported versions

Security fixes are applied to the latest released version. Operators should
track tagged releases and avoid running unmaintained forks with live tokens.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability, token exposure, or a
moderation bypass. Use GitHub's **Report a vulnerability** private reporting
feature for this repository. Include the affected version, impact, reproduction
steps, and a minimal proof of concept with all real Discord IDs and tokens
redacted.

If private reporting is not enabled, contact the repository owner through the
private security contact listed on their GitHub profile. You should receive an
acknowledgement within seven days. Please allow time for a fix and coordinated
release before public disclosure.

Never test against a server or account you do not own or have explicit
permission to assess.
